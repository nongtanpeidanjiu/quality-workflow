# 通用工作流程插件 升级说明

从 0.2.0 升级到 0.4.0 · 适用于 WorkBuddy 桌面版（Mac 和 Windows）

---

## 最近两个版本

### 0.4.0：自动更新

- **装一次，以后自动更新。** 安装时改为从 GitHub 安装，并打开 WorkBuddy 自带的市场自动更新。WorkBuddy 启动时会检查新版本（每天最多一次），有新版本就在后台下载，下次重启后生效。
- **连不上 GitHub 也能升级。** 安装脚本会改用压缩包里的文件安装。插件每天在后台查一次最新版本号，有新版本时在新任务里提醒，对智能体说“更新插件”即可升级。
- **升级后不再重复自检。** 这台电脑通过过一次安装自检，自动升级到新版本后就不会再提醒。

从 0.4.0 以前的版本升级，需要按下面第六节再手动装一次，之后就能自动更新了。

### 0.3.3：修复插件装上了却不生效

- 0.3.2 在 Windows 上可能出现：安装脚本报告“安装成功”，但插件没有启用，WorkBuddy 不加载它。
- 现在安装脚本会确认启用状态真的写进了 WorkBuddy 的设置。WorkBuddy 正在运行、占用设置文件时会重试；仍写不进去，就如实报告“已安装，但没有启用”，并在你退出 WorkBuddy 时自动补上。
- 安装自检发现插件没启用时，会直接说明原因和处理办法。

以下是 0.3 系列相比 0.2.0 的主要改进。

---

## 一、一句话概括

**0.2.0 管的是“它有没有按规矩来”，0.4.0 管的是“结果对不对”。**

0.2.0 能让智能体不乱改、不越界、不跳过检查。但如果它拿到的数据本身有问题，或者一开始就把你的意思理解错了，按规矩走完全程，结果照样是错的。0.4.0 就是为了补上这一块。

---

## 二、最大的变化：怎么判断哪里要重点管

| | 0.2.0 | 0.4.0 |
|---|---|---|
| 判断的对象 | 整个任务 | 任务里的每一样东西 |
| 判断的标准 | 出了错能不能挽回、影响多大、有没有人依赖 | 这一样东西错了，结果会不会跟着错 |
| 结果 | 任务分成低、中、高三档，按档走流程 | 找出决定结果的东西，先核对、再使用；其余从轻 |

“决定结果的东西”通常是这几类：

- 它对你意思的理解：要做成什么、给谁用、用来做什么
- 你给的数据和文件
- 引用的规定、标准、外部事实
- 计算的口径和方法

**举个例子。** 让它统计上季度各产品的投诉率，而你给的投诉记录其实只导出到 9 月 15 日：

- 0.2.0：它判断这是个普通任务，按流程写计划、等你确认、算完、检查，一切合规。但数据少了半个月这件事，没有人去查，算出来的投诉率是偏低的。
- 0.4.0：数据是决定结果的东西，用之前必须先检验。它会在动手算之前告诉你“数据只到 9 月 15 日，缺半个月”，并问你怎么处理。分母用销量还是在用量，它也不会自己选，而是给出推荐，请你定。

## 三、用起来有什么不同

### 1. 开工前先复述，你回一句才往下走

稍大一点的事，它的第一条回复只有几行：它理解你要做成什么、打算分哪几步做，最多再问一个方向性的问题。你确认了，它才继续。

这一步由程序把关：没有你的回复，它写不了任何成果文件。

理解错了，后面做得再好也是白做。这一步就是为了在花力气之前把方向对准。

### 2. 你给的数据和资料，先检验再用

它会检查：是不是该用的那一份、是否完整、前后有没有矛盾、有没有明显异常、是不是现行有效的版本。

发现问题先告诉你，由你决定怎么办。它不会悄悄删数据、补数据或者换一种算法绕过去。

没有问题的资料，它直接采用，不会让你把自己给的东西逐项再确认一遍。

### 3. 只有你能定的事，集中问一次

比如口径怎么选、两份文件用哪一份、资料里互相矛盾的地方以哪个为准。它会把这些事集中起来问，每个都带选项和推荐，你可以直接点选。

检验后没有发现需要你定的事，它就不再打扰你，直接开始做。

### 4. 做完后，逐项核对证据

0.2.0 的独立检查员是把成果通读一遍。0.4.0 的检查员要做两件事：

- 开工前，检查它列的“决定结果的东西”有没有漏项。
- 交付前，逐项核对每一样是不是真的验证过，证据是否成立。少核对一项，程序不放行。

验证方法也有要求：数据要回到原始文件核对，引用要回到官网或原文，计算要换一种方法重算。自己再读一遍觉得没问题，不算验证。

### 5. 核对不了的东西，如实告诉你

查不到一手来源、没法重算的内容，它会明确说“这一项没法核对”，由你决定：继续用（成果里会标明）、换个办法，还是你自己核实后告诉它。它不会把没核对的东西当成核对过的来用。

### 6. 做完后的小修改很快

只改措辞、调版式这类不影响数据和结论的修改，它改完核对一下就交付，不会把整套检查重走一遍。

如果修改动到了数据、口径或结论，才会重新验证受影响的部分。

### 7. 小事照旧直接做

改错别字、改一处措辞、把一列数加起来，这类事它直接做完，不会多问你。

区别在于：它在动手前要向程序声明“这是小事”并说明理由，留有记录。没说给谁看的文档、需要你定口径的统计，不能当成小事直接做。

### 8. 中途改需求，必须重新得到你的回复

目标、范围或完成标准变了，它要把变化告诉你，拿到你新的回复才能继续，不能拿你之前说过的话当作同意。

## 四、程序把关的变化

| 关卡 | 0.2.0 | 0.4.0 |
|---|---|---|
| 你确认之前，不能动成果文件 | 有 | 有 |
| 不能改说好范围以外的文件 | 有 | 有 |
| 不覆盖你手动改过的文件 | 有 | 有 |
| 没通过独立检查，任务不能结束 | 有 | 有 |
| 删除、发布、强制推送等难以收回的动作，执行前先问你 | 有 | 有 |
| 写任何文件之前，必须先复述并得到你的回复，或声明这是小事 | 没有 | **新增** |
| 决定结果的东西没有核对记录，用到它的步骤不能开始 | 没有 | **新增** |
| 决定结果的东西没有全部核对，任务不能结束 | 没有 | **新增** |
| 证据在核对之后被改动，这次核对作废 | 没有 | **新增** |
| 检查报告必须逐项给出结论，缺一项不接受 | 没有 | **新增** |
| 把决定结果的东西降级或删掉，必须有你的原话 | 没有 | **新增** |
| 需求变更后，必须有你新的回复才能继续 | 没有 | **新增** |

需要说明的是：程序能保证“每一样都核对过、有记录”，但判断不了“核对得对不对”。后者靠独立检查员和你。

## 五、安装更省事

| | 0.2.0 | 0.4.0 |
|---|---|---|
| 怎么装 | 把压缩包发给 WorkBuddy，再粘贴一段安装指令 | 把压缩包发给 WorkBuddy，说一句“帮我安装这个插件，按压缩包里《给智能体的安装步骤》做。” |
| 电脑上没有 Python | 装完后自检才发现，需要自己想办法装 | 安装时自动检测，缺了就自动装一份免安装版。不改系统设置，不需要管理员权限 |
| 旧版本 | 自动卸载 | 自动卸载 |
| 点选项按钮回答问题 | 选完还要再打字确认一遍 | 点选即可 |
| 以后的新版本 | 每次都要重新下载压缩包安装 | 自动更新；连不上 GitHub 时提醒你，说“更新插件”即可 |

## 六、怎么升级

1. 在 WorkBuddy 里新建一个任务，把 `quality-workflow-0.4.0.zip` 拖进对话框。
2. 一起发送：

```
帮我安装这个插件，按压缩包里《给智能体的安装步骤》做。
```

3. 看到“安装成功：quality-workflow 0.4.0 已安装并启用。”后，完全退出并重新打开 WorkBuddy。
4. 新建一个任务，随便发一句话，按提示完成安装自检，直到看到“全部通过。插件已经生效。”

Windows 用户在第 3 步重新打开 WorkBuddy 后，请先到“专家·技能·连接器 → 技能 → 套件”确认 quality-workflow 的开关是打开的，没有打开就手动打开并再重启一次。

旧版本会被自动卸载，不需要手动处理。这次装好以后，再有新版本就会自动更新，不用再重复这些步骤。之前项目里的 `.flow` 文件夹是旧任务的记录，可以保留，也可以删掉。

更详细的说明见压缩包里的《安装说明》。
