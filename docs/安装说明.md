# 通用工作流程插件 安装与使用说明

版本 0.3.3 · 适用于 WorkBuddy 桌面版（Mac 和 Windows）

---

## 一、这个插件是做什么的

WorkBuddy 的智能体很能干，但常见几个问题：你没说清楚，它就按自己的理解做；拿到数据和资料不核对就直接用；做着做着范围变了；没仔细检查就说“做好了”。

这个插件的思路是：一项数据错了，方法和过程再漂亮，结果也不可能正确；对你的意思理解错了也是一样。所以先找出这些决定结果的东西，重点管它们，其余从轻。

装上这个插件后，WorkBuddy 会按固定的四步工作：

1. **弄清楚：** 稍大一点的事，它会先用几行话复述它的理解和打算怎么做，等你回一句再往下走。然后找出这件事的结果由哪些东西决定，比如它对你意思的理解、你给的数据、引用的规定、计算的口径。你给的数据和资料，它会先检验再用，发现问题先告诉你。
2. **说定：** 核对数据和资料时，如果发现了只有你才能定的事（口径怎么选、数据不全怎么办、资料互相矛盾），它会集中问你一次，并给出推荐；没发现就不再打扰你。你确认之前，它不会动任何成果文件。
3. **做并查：** 决定结果的东西，先核对、后使用。只改说好的范围。做完由另一个“独立检查员”逐项核对证据，智能体不能自己判定合格。
4. **交付：** 如实告诉你做了什么、关键的东西是怎么核对的、哪些没做、哪些没法核对。

下面几道关卡是由程序把关的，不只是靠智能体自觉：

- 确认之前，不能改成果文件。
- 不能改说好范围以外的文件。
- 决定结果的东西没有核对记录，用到它的步骤不能开始，任务也不能结束。
- 没有通过独立检查，不能结束任务。
- 删除大量文件、强制推送、对外发布这类难以收回的动作，要先问你。

小事不受影响。比如改一个错别字，它会直接改完。

## 二、安装前准备

| 需要 | 说明 |
|---|---|
| WorkBuddy 桌面版 | 已安装，并能正常登录和使用 |
| 安装包 | `quality-workflow-0.3.3.zip` |
| Python | **不需要准备。** WorkBuddy 自带 Python，插件会自动找到。找不到时，安装脚本会自动下载一份免安装版（约 25 MB，装好后约 70 MB），放在你用户目录下的 `.quality-workflow` 文件夹里，不改系统设置，也不需要管理员权限 |
| 网络 | 只有在需要自动下载 Python 时才用到 |

不需要安装 Git、命令行工具或其他软件，也不需要会写代码。

## 三、安装步骤

有两种方法，**推荐方法一**，只需要发一条消息。

### 方法一：让 WorkBuddy 自己安装（推荐）

1. 在 WorkBuddy 里新建一个任务。
2. 把 `quality-workflow-0.3.3.zip` **拖进对话框**。
3. 复制下面这段话，和压缩包一起发送：

```
帮我安装这个插件，按压缩包里《给智能体的安装步骤》做。
```

4. 看到“安装成功：quality-workflow 0.3.3 已安装并启用。”后，**完全退出并重新打开 WorkBuddy，再新建一个任务**，随便发一句话，比如“你好”。
5. 新任务会自动提醒智能体运行安装自检。按它的提示操作，直到看到“全部通过。插件已经生效。”

**Windows 用户请在第 4 步重新打开 WorkBuddy 后多做一步：** 打开“专家·技能·连接器 → 技能 → 套件”，找到 quality-workflow，确认开关是打开的；没有打开就手动打开，再完全退出并重新打开一次 WorkBuddy。Windows 上 WorkBuddy 运行时会占用设置文件，启用状态有可能没写进去。如果安装时看到的是“插件已安装，但没有启用”，或者新任务里没有出现自检提醒，也按这个办法处理。

安装脚本会自动做这些事：检测环境，缺 Python 就自动装一份免安装版；卸载旧版本（包括名字带 `quality-workflow-workbuddy` 的试用版）；把插件复制到你用户目录下的 `.quality-workflow` 文件夹，然后添加市场、安装并启用。下载的压缩包和解压的文件，装好后都可以删掉。

如果安装脚本报错，或者 WorkBuddy 不允许运行它，改用方法二。

### 方法二：手动安装

#### 第 1 步：解压安装包

1. 把 `quality-workflow-0.3.3.zip` **完整解压**。
   - **Mac：** 双击压缩包。
   - **Windows：** 右键压缩包，选“全部解压缩”。不要在压缩包预览窗口里直接操作。
2. 把解压出来的 `quality-workflow-0.3.3` 文件夹，放到一个**以后不会删、不会移动**的位置。例如：
   - **Mac：** “文稿”文件夹，即 `/Users/你的用户名/Documents/`
   - **Windows：** “文档”文件夹，即 `C:\Users\你的用户名\Documents\`

   WorkBuddy 安装时会记住这个位置，以后移走或删掉会出问题。

解压后的文件夹里应该有：

```
quality-workflow-0.3.3/
├── 安装说明.md
├── 安装说明.html
├── install.mjs           ← 方法一用的安装脚本
└── marketplace/          ← 第 3 步要选的就是这个文件夹
    ├── .codebuddy-plugin/
    └── plugins/
```

`.codebuddy-plugin` 是隐藏文件夹，Mac 上默认看不到，这是正常的，不影响安装。

#### 第 2 步：卸载旧版（没装过可跳过）

如果你以前装过名字带 `quality-workflow-workbuddy` 的试用版，先卸载它，否则两个版本会同时运行、互相干扰：

1. 打开 WorkBuddy，进入“套件”页面（位置见第 3 步）。
2. 找到 `quality-workflow-workbuddy`，先停用，再卸载。
3. 如果有名为 `quality-workflow-workbuddy-local-trial` 或 `quality-workflow-workbuddy-preview` 的市场，也一并移除。

#### 第 3 步：添加插件市场

1. 打开 WorkBuddy。
2. 点左侧的 **“专家·技能·连接器”**，再点页面顶部的 **“技能”**。
3. 页面中间有一行 **“推荐　SkillHub　套件”**，点 **“套件”**。
4. 在“套件”页面点 **“添加市场”**。它在市场名称那一行的**最右端**；窗口窄的时候会被挤到看不见的地方，请把 WorkBuddy 窗口拉宽或最大化，或在这一行上横向滑动到最右边。注意不是右上角的“添加技能”，那里只能装单个技能，装不了完整插件。
5. 在弹出的输入框里，粘贴第 1 步解压出来的 **`marketplace` 文件夹的完整路径**。注意是 `marketplace` 这一层，不是外面的 `quality-workflow-0.3.3`，也不是里面的 `plugins`。例如：

   ```
   Mac：     /Users/你的用户名/Documents/quality-workflow-0.3.3/marketplace
   Windows： C:\Users\你的用户名\Documents\quality-workflow-0.3.3\marketplace
   ```

   **路径要换成你电脑上的实际位置。** 复制完整路径的方法：
   - **Mac：** 在访达里找到 `marketplace` 文件夹，右键它，按住 Option 键，菜单里会出现“将‘marketplace’拷贝为路径名称”，点它。
   - **Windows：** 打开 `marketplace` 文件夹，点一下窗口上方的地址栏，复制里面的路径。

6. 添加成功后，会出现一个名为 **`quality-workflow-market`** 的市场。

#### 第 4 步：安装插件

1. 在 `quality-workflow-market` 市场里找到 **`quality-workflow`**。
2. 核对版本号是 **0.3.3**，点击安装。
3. 如果 WorkBuddy 提示“这个插件会运行本地脚本，是否信任”，核对名称无误后确认。
4. 确认插件状态是“已启用”。

**添加市场不等于安装插件，** 第 3 步和第 4 步都要做。

#### 第 5 步：运行安装自检（必须做）

1. 在 WorkBuddy 里**新建一个任务**。必须是新任务，旧任务不会加载刚装的插件。
2. 把下面这段话原样复制，发给 WorkBuddy：

```
请运行 quality-workflow 插件的安装自检。
如果有未通过的项目，按自检给出的建议修好环境，修完再运行一次，直到全部通过。
修复时只处理环境问题（例如安装 Python、启用插件、重启 WorkBuddy），
不要修改插件的规则文件、hook 配置或任务记录来让检查通过。
```

3. 等它运行完。看到下面这句话，就表示安装成功：

```
全部通过。插件已经生效。
```

自检会检查五件事：

| 检查项 | 意思 |
|---|---|
| Python | 能不能找到可用的 Python |
| 插件文件 | 安装包是否完整 |
| 关卡逻辑 | 模拟一次“没确认就写文件”，看会不会被拦下 |
| WorkBuddy 调用插件 | WorkBuddy 是不是真的在运行这个插件，而不只是把文件放在那里 |
| 旧版插件 | 有没有和旧版本冲突 |

**在通过自检之前，你每次新建任务，WorkBuddy 都会先提醒运行自检。** 这是正常的，通过一次之后就不会再提醒。

## 四、安装后试用一次（建议）

建议先用一个练习文件夹，亲眼看一看插件是怎么工作的。

### 1. 准备练习文件夹

在桌面新建一个文件夹，叫“插件练习”，在里面新建一个文本文件 `说明.md`，随便写几句话。

### 2. 在 WorkBuddy 里打开这个文件夹

新建任务，把项目目录设成“插件练习”文件夹，然后发送：

```
帮我把 说明.md 改写得更正式一些，这份文件以后要发给客户看。
```

### 3. 你应该看到

| 阶段 | 应该发生 | 不应该发生 |
|---|---|---|
| 开始 | 它问你客户是谁、需要多正式，或者先给你一段小样 | 不问任何问题，直接改完 |
| 确认 | 给你一页确认页：它的理解、哪些东西要重点核对、打算怎么做，请你确认 | 还没确认就修改了 `说明.md` |
| 你回复“可以，就这样做” | 开始修改，只动 `说明.md` | 修改或新建其他文件 |
| 完成 | 调用独立检查员核对，然后告诉你改了什么、关键的东西是怎么核对的，以及“未经人工确认”的部分 | 自己说一句“已完成”就结束 |

如果“不应该发生”的事情发生了，请按第八节反馈。

练习结束后，文件夹里会多出一个 `.flow` 隐藏文件夹，这是任务记录，可以直接删掉。

## 五、日常怎么用

**像平时一样提要求就行，** 不用记任何命令。几个让它更好用的习惯：

- **说清楚给谁用、用来做什么。** 比如“这份周报是给总监看的”，比“帮我优化一下周报”效果好得多。
- **说清楚哪些不能动。** 比如“只改 docs 文件夹，代码不要动”。
- **中途改主意就直接说。** 比如“不对，读者改成客户”。它会说明哪些已做的内容要调整，并重新和你确认。
- **想让它停下，就说“先不做了”。** 它会保存进度，标明哪些还没完成。
- **做完后想小改，直接说。** 只改措辞这类不影响数据和结论的改动，它会直接改好并核对，不会把整套检查重走一遍。
- **它问你确认时，请明确回复。** “可以”“就这样做”都行。没有回复，它不会继续改文件。
- **它列出的“重点核对的东西”，你可以增删。** 比如“这份数据也要核对”“这个不用管”。哪些东西决定结果，往往你最清楚。
- **它说“这一项没法核对”时，由你决定。** 可以让它继续用（成果里会标明），换个办法，或者你自己核实后告诉它。

插件不给任务分等级，而是看这件事里有没有决定结果的东西：

| 任务 | 例子 | 插件会怎么做 |
|---|---|---|
| 没有决定结果的东西 | 改个错别字、改一处措辞 | 直接做完 |
| 有，但当场就能核对清楚 | 把表格第三列求和 | 核对后直接做，并告诉你是怎么核对的 |
| 你的意思没说清 | “优化一下这段话” | 先问一个关键问题，或先给小样、大纲 |
| 有需要你确认的，或步骤较多 | 统计各产品投诉率、按新规定修改手册 | 先检验数据和资料，给你确认页，等你确认；做完逐项核对 |
| 难以收回的动作 | 发布、批量删除、强制推送 | 无论什么任务，执行前都先问你 |

## 六、常见问题

**问：让 WorkBuddy 自己安装时报错？**
答：把安装脚本的输出发给分享插件给你的人，然后改用方法二手动安装。如果脚本说找不到 WorkBuddy 的安装位置，多半是 WorkBuddy 装在了非默认位置，手动安装不受影响。

**问：安装后 WorkBuddy 没有任何变化？**
答：确认第 3 步和第 4 步都做了，而且插件已启用。然后一定要**新建任务**，旧任务不会加载新插件。还不行就完全退出 WorkBuddy 再打开。

**问：找不到“添加市场”按钮？**
答：先点“专家·技能·连接器 → 技能”页面中间的“套件”。按钮在市场名称那一行的最右端，窗口窄时会被挤出可见区域，把窗口拉宽或在这一行上横向滑动就能看到。它不在右上角的“添加技能”里。

**问：添加市场后看不到插件？**
答：多半是选错了文件夹。要选 `marketplace` 这一层。也可能是压缩包没有完整解压，请重新解压后再添加。

**问：自检说“找不到 Python”？**
答：WorkBuddy 通常自带 Python，正常情况下不会出现这个问题。出现时，让 WorkBuddy 按自检的建议安装 Python，装好后**完全退出并重新打开 WorkBuddy**，再新建任务运行自检。你也可以自己从 [python.org](https://www.python.org/downloads/) 下载安装。

**问：自检说“WorkBuddy 调用插件”未通过？**
答：说明插件文件在，但 WorkBuddy 没有运行它。请确认插件已启用，新建一个任务，在新任务里再运行自检。如果仍不通过，重启 WorkBuddy 再试。

**问：自检说“旧版插件”冲突？**
答：按第 2 步卸载旧版，再新建任务运行自检。

**问：每次开新任务都提醒运行自检，很烦？**
答：说明自检还没有全部通过。把未通过的项目修好就不会再提醒了。

**问：它总是问我问题，能不能直接做？**
答：需求说得越清楚，它问得越少。你也可以直接回答“你来定”，它会按推荐方案做，并写明它做了哪些假设。

**问：我想临时关掉插件？**
答：在插件管理里停用 `quality-workflow` 即可，需要时再启用。

**问：项目里多出来的 `.flow` 文件夹是什么？**
答：是任务记录，包括需求、计划、确认记录和检查报告。任务结束后可以删除。如果项目用 Git 管理，它默认不会被提交。

## 七、更新和卸载

### 更新到新版本

1. 在插件管理里停用并卸载旧版 `quality-workflow`，再移除 `quality-workflow-market` 市场。
2. 按第三节，用新的安装包重新安装。
3. 新建任务，运行一次安装自检。

### 卸载

1. 在插件管理里停用并卸载 `quality-workflow`。
2. 移除 `quality-workflow-market` 市场。
3. 删除解压出来的 `quality-workflow-0.3.3` 文件夹。
4. 可选：删除用户目录下的 `.quality-workflow` 文件夹（Mac 在 `/Users/你的用户名/`，Windows 在 `C:\Users\你的用户名\`），以及各项目里的 `.flow` 文件夹。

**不要手动删除 WorkBuddy 自己的设置文件夹，** 里面还有你的其他插件和账号设置。

## 八、遇到问题怎么反馈

把下面的内容填好，连同自检的完整输出一起发给分享插件给你的人：

```
电脑系统：Mac / Windows（版本号）
WorkBuddy 版本：
插件版本：0.3.3
卡在哪一步：
自检结果（原样粘贴）：
发生了什么、你期望发生什么：
```

**请不要发送密码、登录信息，或者包含敏感内容的项目文件。**

## 九、说明与边界

- **它不是安全软件。** 程序关卡能挡住大多数误操作，但如果智能体用特殊方式绕过，或者 WorkBuddy 没有运行插件，关卡就不起作用。重要的成果仍需要你自己把关。
- **独立检查员也是智能体，** 它的检查不等于人工审核，也不等于业务或法律上的认可。
- **程序只能保证“有没有核对”，不能保证“核对得对不对”。** 它能强制每个决定结果的东西都有核对记录，判断不了记录的内容。内容靠独立检查员和你。
- **任务记录保存在你的电脑上，** 包括你说过的原话和文件摘要，插件不会上传任何内容。转发项目文件给别人时，可以先删掉 `.flow` 文件夹。另外，为了让它能引用你最初提的要求，插件会在你的用户目录下的 `.quality-workflow` 文件夹里暂存最近 30 条消息，只在本机，建立任务记录后即清除。
- **找全“决定结果的东西”靠模型的能力。** 较强的模型找得更全；较弱的模型可能漏项，或把有数据、有计算的任务当成小事直接做。
