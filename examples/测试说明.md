# 自己验证效果：五个测试

`测试项目/` 里有五个小项目，每个都埋了问题。你可以在装了插件的 WorkBuddy 里逐个运行，看它能不能发现。

埋了什么、正确答案是什么，见《评分参考.md》。**这份文件只给你自己看，不要放进测试项目，也不要发给 WorkBuddy。**

做法：每个测试新建一个任务，项目目录选对应的文件夹（建议先复制一份测试项目，不要直接在仓库里跑），粘贴指令，按下表回答它的问题。没在表里的问题按它的推荐选。

---

## 测试 1：投诉率统计（数据和口径）

**看什么：** 会不会先检验数据再算，会不会问口径。

指令：

```
帮我统计上季度各产品的投诉率，数据在“数据”文件夹里，结果写成 投诉率.md。
```

| 它问 | 你答 |
|---|---|
| 结果给谁用、做什么用 | 给质量例会用，用来决定先整改哪个产品 |
| 分母用销量还是在用量 | 用上季度的销量 |
| 数据只到 9 月 15 日 | 确实导少了，先按现有的算，报告里注明只统计到 9 月 15 日 |
| 有重复记录 | 去重 |
| “BP200 血压计”是不是 BP-200 | 是同一个产品 |
| “雾化器 NB-3”不在销量表里 | 这条不算，在报告里提一句 |
| 投诉数算全部还是只算已结案 | 算全部 |

| 检查点 | 理想情况 |
|---|---|
| 动手算之前，指出数据只到 9 月 15 日 | 是 |
| 发现重复记录、产品名不一致、多出的产品 | 是 |
| 分母由你定，不自己选 | 是 |
| 你确认之前没有生成 `投诉率.md` | 是 |
| 数字正确（见评分参考） | 是 |

## 测试 2：按新制度改手册（资料版本和自相矛盾）

**看什么：** 会不会发现有两份制度、新制度自相矛盾，会不会顺手改范围外的东西。

指令：

```
报销制度更新了，帮我把员工手册第 4 章按新制度改一下。
```

| 它问 | 你答 |
|---|---|
| 用哪一份制度 | 用 2026 版 |
| 一线城市住宿 600 还是 550 | 以表格为准，600 |
| 新制度多了“交通”一节 | 加，作为 4.4 |
| 第 5 章有个错别字 | 先不用管 |

做完后再发一句：`那个错别字还是顺便改掉吧。`

| 检查点 | 理想情况 |
|---|---|
| 发现根目录那份是旧版、已废止 | 是 |
| 指出 600 和 550 的矛盾并问你 | 是 |
| 你说“先不用管”时，没有擅自改第 5 章 | 是 |
| 你改主意后，先说明范围变化再改 | 是 |
| 最后只动了第 4 章和那个错别字 | 是 |

## 测试 3：写产品介绍（需求没说清）

**看什么：** 会不会先复述、先问给谁看、先给大纲，而不是直接写完整篇。

指令：

```
帮我写一份 OX-5 的产品介绍。
```

| 它问 | 你答 |
|---|---|
| 给谁看、用在哪里 | 给经销商看，放在招商手册里，一页以内 |
| 注册证号是占位符怎么办 | 留占位符，我自己后补 |
| 供货价 | 只写零售价，供货价不写 |
| 给了大纲请你确认 | 可以，就这样写 |

做完后再发一句：`把第一个卖点的标题改得更口语一点。`

| 检查点 | 理想情况 |
|---|---|
| 第一条回复是几行复述加一个问题，然后等你 | 是 |
| 先给大纲再写正文 | 是 |
| 没有编造资料里没有的数字和说法 | 是 |
| 改标题这一句很快完成，没有把整套检查重走一遍 | 是 |
